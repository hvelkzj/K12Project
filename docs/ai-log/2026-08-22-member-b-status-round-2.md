# 2026-08-22 B 家长端第二轮状态补齐

## 目标

根据第二轮任务说明，补齐家长端通知已读、首页未读数量和请假审批状态展示。

## 完整提示词

用户先说明：“这是第二轮的任务，刚刚错误的让你先进行了第三轮的任务。”

随后要求基于第二轮任务资料处理。

第二轮任务要点：

- 接入 `PATCH /parent/notifications/:notificationId/read`。
- 首页显示未读通知数量。
- 打开通知后调用接口，成功后再更新已读状态。
- 已读请求失败时保持未读状态并显示错误。
- 请假页面展示 `PENDING`、`APPROVED`、`REJECTED`。
- 展示审核意见和更新时间。
- 刷新当前学生概览后同步请假状态，并保持当前学生选择。
- 防止通知已读和请假提交重复点击。
- `401` 返回登录页；其他业务错误保留会话。
- 页面运行时不得读取业务 Mock。

## AI 回复摘要

- 确认第三轮误做分支已存在并已推送，不继续修改。
- 从最新 `develop` 创建正确第二轮分支 `feature/B-parent-status-round-2`。
- 复用通知已读、刷新和错误处理相关家长端代码。
- 补齐第二轮专属验收点：首页未读通知数、请假状态中文、审核意见、更新时间。

## 人工判断

- `Notification.readAt` 已足够表达已读状态，不需要修改公共类型。
- API 已提供通知已读接口，家长端只接入调用和页面状态更新。
- 请假审批由后台执行，家长端负责刷新概览展示最新状态。

## 执行的修改

- `parentBusinessClient` 增加 `markNotificationRead`。
- 通知页增加“查看并标记已读”操作。
- 已读成功后才替换页面中的普通通知或调课通知。
- 首页统计未读通知数量。
- 请假页展示 `PENDING`、`APPROVED`、`REJECTED` 的家长可读文案。
- 请假记录展示审核意见和更新时间。
- 请假提交成功后刷新当前学生概览。
- 刷新当前学生概览保留当前学生选择。
- 概览加载增加请求序号保护，避免旧请求覆盖新学生数据。
- 补充单元测试和交付记录。
