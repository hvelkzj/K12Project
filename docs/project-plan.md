# 项目计划、分工与交付边界

## 1. 目标与范围

截止时间：2026-08-27。建议把 2026-07-27 至 2026-08-23 作为四周开发周期，2026-08-24 至 2026-08-27 作为联调、报告和答辩缓冲期。

### 必做闭环

1. 家长端小程序：查看课表/通知、请假申请、查看反馈、反馈认可或异议。
2. 学生端 Web/Pad：查看课件、提交作业、查看批改和课后反馈。
3. 教师/班主任端：签到、发课后反馈、批改作业、发起调课/请假、查看班级跟进。
4. 教务后台：排课、审批请假/调课、代课安排、处理家长异议工单。
5. 系统总后台：机构/校区/账号管理、角色权限、全局数据看板、操作审计。

### 明确不做或简化

在线支付、复杂营销、实时音视频、真实短信和地图服务不纳入核心范围；使用模拟支付/通知和本地文件上传即可。

## 2. 五人分工（工作量尽量均衡）

| 成员 | 主责 | 交付物 | 协作责任 |
|---|---|---|---|
| A 组长/架构 | 需求、数据库、认证、RBAC、集成 | ER 图、登录鉴权、权限中间件、CI、最终集成 | 审核公共接口和迁移 |
| B | 家长端 + 通知 | 课表、请假、通知、家长反馈处理 | 对接调课状态和工单状态 |
| C | 学生端 + 作业 | 课件、作业提交、批改结果、学生首页 | 对接教师批改 API |
| D | 教师/班主任端 | 签到、反馈、批改、请假/调课申请、班级跟进 | 提供业务事件和状态流转 |
| E | 教务/系统后台 + 测试 | 排课、审批、代课、工单、后台权限视图、测试数据 | 负责跨端验收脚本和演示账号 |

每人承担一个主端/主域，同时各自负责该域的前端、接口联调、测试和报告材料，避免“只写页面”或“只写后端”。组长额外承担集成工作，因此 A 的业务模块略少；E 的后台较重，B/C/D 各自负责补齐跨端测试和截图。

## 4. 每周统一会议与验收

每周一冻结本周任务，每晚异步更新；周三检查接口契约，周六演示，周日只修复已登记问题。每个功能必须提供成功、重复操作、无权限、空数据和异常网络至少五类测试。
