## 目标

把教师端从纯 Mock 页面升级为使用真实认证、公共类型和业务 API 的功能模块，并补齐教师工作区测试。

开发时使用可注入的 Mock `fetch` 测试，不需要等待 A 的后端实现完成。

## 修改范围

允许修改：

- `apps/teacher-web`
- 教师工作区依赖声明
- 根 `package-lock.json` 中由教师工作区测试依赖产生的记录
- D 本轮交付记录和 AI 记录

禁止修改 API、公共类型和其他前端。公共字段不足时只在 PR 中提出。

## 接口

| 方法与路径 | 用途 |
|---|---|
| `GET /teacher/overview` | 加载教师可见业务数据 |
| `PUT /teacher/attendance` | 保存课次签到 |
| `POST /teacher/assignments` | 发布作业 |
| `PATCH /teacher/submissions/:submissionId` | 批改作业 |
| `POST /teacher/feedback` | 发送课后反馈 |
| `POST /teacher/schedule-changes` | 提交调课申请 |

认证继续使用 `POST /auth/login`、`GET /auth/me` 和 `POST /auth/logout`。

## 实现要求

1. 新增可注入 `fetch` 的教师认证客户端和业务客户端。
2. 使用现有 `VITE_API_BASE_URL`、`sessionStorage` 和 `k12AccessToken` 约定。
3. 只允许 `TEACHER` 和 `HOMEROOM_TEACHER` 登录教师端。
4. 非教师角色登录后应撤销刚创建的服务端会话。
5. 支持刷新后的会话恢复和退出。
6. 删除 `teacher_d`、手动角色切换和 Mock 登录提示。
7. 删除小写 `teacher`、`headTeacher` 角色和重复业务状态。
8. 角色、签到、作业、提交、反馈和调课类型统一从 `@k12/shared` 使用。
9. 登录成功后加载教师概览。
10. 签到、发布、批改、反馈和调课操作必须等待接口成功后更新页面。
11. 接口失败时保留用户输入，不显示假成功。
12. 增加加载中、空数据、请求失败和重试状态。
13. `401` 清理 Token 并回到登录页。
14. `403`、`404`、`409`、`422` 显示服务端业务错误。
15. 页面运行时不再读取业务 Mock。
16. 给教师工作区增加 `test` 脚本、测试文件和必要开发依赖。
17. 只使用根锁文件，不创建教师端子锁文件。

## 必测场景

- 任课教师和班主任登录成功。
- 家长、学生、教务和系统管理员被拒绝。
- 有效会话恢复、过期会话、退出失败时本地 Token 清理。
- 教师只能操作本人授课课程。
- 班主任查看负责班级，但不能代替其他教师执行教学写操作。
- 签到成功和重复签到。
- 作业标题、内容、截止时间和班级课程校验。
- 批改分数 0–100、教师评语和订正状态。
- 反馈必填字段和重复反馈。
- 调课日期、时间、原因和重复申请。
- `401`、`403`、`409` 和网络错误。
- 失败操作不能改变列表状态或显示假成功。
