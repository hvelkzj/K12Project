## 目标

保留现有家长端页面、视觉和真实认证，把运行时业务数据从本地 Mock 改为 A 规定的业务 API。

开发时使用可注入的 Mock `fetch` 测试，不需要等待 A 的后端实现完成。

## 修改范围

允许修改：

- `apps/parent-web`
- B 本轮交付记录
- B 本轮 AI 记录

禁止修改 API、公共类型和其他前端。公共字段不足时只在 PR 中提出。

## 接口

| 方法与路径 | 用途 |
|---|---|
| `GET /parent/students` | 获取当前家长绑定的学生 |
| `GET /parent/students/:studentId/overview` | 获取所选学生的课表、请假、通知和反馈 |
| `POST /parent/leave-requests` | 提交请假 |
| `PATCH /parent/feedback/:feedbackId` | 确认反馈或提出异议 |

所有请求使用现有 `sessionStorage` Token 和 `VITE_API_BASE_URL`。

## 实现要求

1. 新增可注入 `fetch` 的家长业务客户端。
2. 复用现有认证客户端，不复制第二套 Token 管理逻辑。
3. 登录后先加载绑定学生，再加载第一个学生的概览。
4. 切换学生后重新请求该学生概览，不能混用上一个学生的数据。
5. 请假成功后把服务端返回的 `LeaveRequest` 写入列表。
6. 请假失败时保留课程、原因和联系电话。
7. 确认反馈成功后显示 `CONFIRMED`。
8. 提出异议时必须填写内容，成功后显示 `DISPUTED`。
9. 调课通知展示原日期时间、新日期时间、原教师和代课教师。
10. 增加加载中、空数据、请求失败和重试状态。
11. 业务接口返回 `401` 时清除 Token 并回到登录页。
12. `403`、`404`、`409`、`422` 使用服务端错误信息，不显示假成功。
13. 页面运行时不再导入业务 Mock；Mock 只保留在测试夹具中。
14. 不改变现有蓝色侧栏、窄屏底部导航和当前页面语义。

## 必测场景

- 登录后加载绑定学生和默认学生概览。
- 切换学生时数据全部更新。
- 空绑定和空列表。
- 请假成功、重复请假、字段错误和网络错误。
- 请求失败后表单内容仍然存在。
- 反馈确认和异议内容必填。
- 调课通知字段完整。
- `401` 清理 Token；其他业务错误保留登录状态。
- 失败操作不能出现“已提交”或“已保存”。
