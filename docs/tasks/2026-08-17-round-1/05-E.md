# E 成员本轮任务：后台接入业务 API

发布日期：2026-08-17

提交目标：2026-08-20 22:00 前

目标分支：`develop`

个人分支：`feature/E-admin-api-round-1`

本轮只完成本文档任务。原每周任务停止执行；PR 审核和问题修复完成前，不开始下一轮。

## 目标

保留现有后台认证和八个页面，把调课审批、代课、反馈工单、用户和看板改为读取业务 API。

开发时使用可注入的 Mock `fetch` 测试，不需要等待 A 的后端实现完成。

## 修改范围

允许修改：

- `apps/admin-web`
- E 本轮交付记录
- E 本轮 AI 记录

禁止修改 API、公共类型和其他前端。公共字段不足时只在 PR 中提出。

## 接口

| 方法与路径 | 用途 |
|---|---|
| `GET /admin/overview` | 加载后台可见数据 |
| `PATCH /admin/schedule-changes/:changeId/review` | 审批调课 |
| `PATCH /admin/schedule-changes/:changeId/substitute` | 安排代课 |
| `PATCH /admin/work-orders/:workOrderId` | 开始或关闭反馈工单 |

所有请求复用现有后台认证 Token。

## 实现要求

1. 新增可注入 `fetch` 的后台业务客户端。
2. 复用现有认证客户端，不复制第二套 Token 管理。
3. 登录后加载后台概览。
4. 教务只展示所属校区的数据。
5. 系统管理员展示全部校区的数据。
6. 审批成功后使用服务端返回值更新申请。
7. 拒绝调课时必须填写原因。
8. 已审批申请不能重复审批。
9. 只有 `APPROVED` 申请可以安排代课。
10. 代课教师必须同校区且不能是原教师。
11. 工单 `START` 成功后显示 `PROCESSING`。
12. 工单 `CLOSE` 前必须填写处理结果。
13. 已关闭工单不能再次处理。
14. 工作台和看板数据从后台概览动态计算，不保留写死统计值。
15. 增加加载中、空数据、请求失败和重试状态。
16. `401` 清理 Token 并回到登录页。
17. `403`、`404`、`409`、`422` 显示服务端业务错误，不修改本地状态。
18. 页面运行时不再读取业务 Mock。
19. 删除“第一周演示”和类似过期文案。

## 必测场景

- 教务只能读取所属校区。
- 系统管理员可以读取全部校区。
- 审批通过、拒绝原因必填和重复审批。
- 只有已通过申请可以安排代课。
- 代课教师同校区、不能是原教师。
- 工单开始处理、关闭结果必填和重复关闭。
- 看板统计随概览数据变化。
- `401`、`403`、`409` 和网络错误。
- 失败操作不能改变页面状态或显示假成功。
