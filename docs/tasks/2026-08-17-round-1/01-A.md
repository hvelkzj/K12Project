个人分支：`feature/A-business-api-round-1`

本轮只完成本文档任务。原每周任务停止执行；PR 审核和问题修复完成前，不开始下一轮。

## 目标

在现有认证 API 基础上增加共享内存业务数据和业务接口，让 B、C、D、E 后续接入同一个后端数据源。

本轮不接 PostgreSQL，不实现真实文件上传，不修改四个前端。

## 修改范围

允许修改：

- `apps/api`
- `docs/api-field-contract.md`
- A 本轮交付记录
- A 本轮 AI 记录

禁止修改：

- `apps/parent-web`
- `apps/student-web`
- `apps/teacher-web`
- `apps/admin-web`
- 已确定的公共字段名称、ID 类型、角色值和状态值

公共字段不足时，先在 PR 中写明业务场景、字段、类型和影响，不直接建立第二套字段。

## 固定接口

所有接口使用现有 Bearer Token，错误响应使用 `ApiError`。

### 家长端

| 方法与路径 | 请求 | 成功响应 |
|---|---|---|
| `GET /parent/students` | 无 | `ParentStudentBinding[]` |
| `GET /parent/students/:studentId/overview` | 路径中的学生 ID | 学生、课表、课程、教师、请假、通知、调课通知和反馈 |
| `POST /parent/leave-requests` | `studentId`、`scheduleId`、`reason`、`contactPhone` | `LeaveRequest` |
| `PATCH /parent/feedback/:feedbackId` | `status`、`parentResponse` | `StudentFeedback` |

### 学生端

| 方法与路径 | 请求 | 成功响应 |
|---|---|---|
| `GET /student/overview` | 无 | 当前学生、课程、教师、课件、作业和提交记录 |
| `POST /student/submissions` | `assignmentId`、`content`、`attachments` | `Submission` |

### 教师端

| 方法与路径 | 请求 | 成功响应 |
|---|---|---|
| `GET /teacher/overview` | 无 | 课表、班级、学生、课程、签到、作业、提交、反馈和调课申请 |
| `PUT /teacher/attendance` | `scheduleId`、`records` | `AttendanceRecord[]` |
| `POST /teacher/assignments` | 班级、课程、课次、标题、内容、附件、截止时间、迟交规则 | `Assignment` |
| `PATCH /teacher/submissions/:submissionId` | `score`、`teacherComment`、`correctionRequired` | `Submission` |
| `POST /teacher/feedback` | 课次、学生、表现、优点、待提升、建议 | `StudentFeedback` |
| `POST /teacher/schedule-changes` | 课次、原因、建议日期、开始时间、结束时间 | `ScheduleChange` |

### 后台

| 方法与路径 | 请求 | 成功响应 |
|---|---|---|
| `GET /admin/overview` | 无 | 校区、班级、课程、课表、账号、教师、调课申请和反馈工单 |
| `PATCH /admin/schedule-changes/:changeId/review` | `decision`、`decisionNote` | `ScheduleChange` |
| `PATCH /admin/schedule-changes/:changeId/substitute` | `substituteTeacherId`、`substituteNote` | `ScheduleChange` |
| `PATCH /admin/work-orders/:workOrderId` | `action: 'START' \| 'CLOSE'`、`result?` | `FeedbackWorkOrder` |

概览响应只组合现有公共类型，不新增同名业务实体。

## 实现要求

1. 建立可注入、可独立创建的内存业务仓库。
2. 初始数据使用公共数字 ID、角色、状态和六角色账号关系。
3. 服务重启后恢复初始数据。
4. 测试可以注入固定时钟；业务时间由服务端生成。
5. 用户 ID、审批人 ID、教师 ID 和家长 ID 从当前会话取得，不信任请求体中的身份字段。
6. 家长只能访问已绑定学生。
7. 学生只能访问本人数据。
8. 任课教师只能写本人授课班级的数据。
9. 班主任可以查看负责班级；教学写操作仍要求本人授课。
10. 教务只能访问所属校区，系统管理员可以访问全部校区。
11. 不允许重复提交、重复审批、重复关闭工单或重复签到。
12. 拒绝调课时必须填写原因。
13. 代课教师必须同校区、不能是原教师，并检查时间冲突。
14. 作业分数限制为 0–100。
15. 不允许迟交时，超过 `dueAt` 的提交返回错误。
16. 订正提交增加 `attempt`，不能覆盖旧提交。
17. 家长提出反馈异议时自动建立反馈工单。
18. 安排代课后自动建立家长调课通知。

## 错误状态

| HTTP 状态 | 场景 |
|---:|---|
| `401` | 未登录、Token 缺失或会话失效 |
| `403` | 角色不允许或超出数据范围 |
| `404` | 业务数据不存在 |
| `409` | 重复操作或当前状态不允许操作 |
| `422` | 字段错误或业务校验失败 |

不得把正常的业务错误统一返回为 `500`。

## 必测场景

- 六种角色的允许和拒绝范围。
- 家长访问未绑定学生。
- 学生访问其他学生数据。
- 教师访问其他教师课程。
- 教务跨校区访问。
- 作业发布、提交、重复提交、截止限制、批改、订正和历史保留。
- 调课申请、审批、拒绝原因、代课限制和通知生成。
- 反馈发送、家长确认、家长异议、工单创建、开始处理和关闭。
- 每个测试创建独立业务仓库，不依赖测试执行顺序。
