# C 成员本轮任务：学生端接入业务 API

发布日期：2026-08-17

提交目标：2026-08-20 22:00 前

目标分支：`develop`

个人分支：`feature/C-student-api-round-1`

本轮只完成本文档任务。原每周任务停止执行；PR 审核和问题修复完成前，不开始下一轮。

## 目标

保留现有学生端认证和作业列表视觉页面，把首页、课件、作业和提交记录改为读取业务 API。

开发时使用可注入的 Mock `fetch` 测试，不需要等待 A 的后端实现完成。

## 修改范围

允许修改：

- `apps/student-web`
- C 本轮交付记录
- C 本轮 AI 记录

禁止修改 API、公共类型、其他前端和 `AssignmentList.vue` 的既定主视觉方向。公共字段不足时只在 PR 中提出。

## 接口

| 方法与路径 | 用途 |
|---|---|
| `GET /student/overview` | 获取当前学生、课程、教师、课件、作业和提交记录 |
| `POST /student/submissions` | 首次提交或订正提交 |

提交请求只发送 `assignmentId`、`content` 和 `attachments`。学生 ID、提交时间和 `attempt` 由后端确定。

## 实现要求

1. 新增可注入 `fetch` 的学生业务客户端。
2. 复用现有认证服务和 Token 处理。
3. 登录后加载学生概览。
4. 首页统计、课件、作业列表、详情和结果使用同一次概览数据。
5. 提交成功后重新加载概览，更新列表状态和完成率。
6. `REVISION_REQUIRED` 时允许再次提交；页面显示完整 `attempt` 历史。
7. 不允许迟交时，前端可以提前提示，但以服务端响应为最终结果。
8. 附件只发送 `FileSummary` 元数据，本轮不实现真实上传。
9. 增加加载中、空数据、请求失败和重试状态。
10. 业务接口返回 `401` 时清除 Token 并回到登录页。
11. `403`、`404`、`409`、`422` 显示服务端信息，不改变为会话过期。
12. 请求失败时保留正文和附件选择。
13. 页面运行时不再读取业务 Mock；现有 Mock 可以转为测试夹具。
14. 保留作业列表、详情、提交和结果之间的现有页面流程。

## 必测场景

- 概览加载、空课件和空作业。
- 首次提交成功后状态和完成率更新。
- 重复提交返回冲突。
- 截止后且不允许迟交时被拒绝。
- 正文和附件不能同时为空。
- 附件类型或大小错误。
- 订正产生新 `attempt`，旧记录仍可查看。
- 批改结果和教师评语显示。
- `401`、网络错误和业务错误分别处理。
- 失败提交不能清空用户输入或显示假成功。
